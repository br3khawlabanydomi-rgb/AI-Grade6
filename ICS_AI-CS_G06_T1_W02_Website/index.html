Explanation and examples

A rule-based system and a learning system can do the same job yet work in completely different ways. In a rule-based system, a person decides the logic in advance and writes it as fixed steps; the data flows through those steps unchanged. In a learning system, a person does not write the logic - they collect data, label it, and let the system build a model that captures the pattern. Two features separate them cleanly. First, where the logic comes from: written by a person versus learned from data. Second, how they handle something new: a rule-based system can only handle cases its rules cover, while a learning system can generalise to new cases that resemble its examples. The model is the heart of a learning system - it is the pattern learned from the data, and it is only as good as the examples it was trained on. Knowing these features lets you classify almost any system you meet.

Source activity

Hands-on activity guide Overview: A structured classification activity: students build a feature chart, then use it to classify everyday UAE systems, defending each choice with a feature rather than a surface trait. Unplugged; any AI shown is a teacher board demo. Grouping / timing: Pairs, with whole-class charting. Tool: Feature-chart handout and everyday-system cards. - Account-free for students; teacher-only board demo for any live tool. Facilitation steps: 1. Copy the two-column feature chart. 2. Add one example to each row with your partner. 3. Classify two everyday systems using the chart. 4. For each, underline the feature that decided your answer. 5. Write two sentences using data and model correctly. Unplugged fallback: Runs fully unplugged using only the printed chart and cards; no demo required. Formative assessment (aligned to the objectives) Formative check. • Targets: Directly checks 'recognises the difference between rule-based and learning systems' • Check: Exit ticket: classify two systems and give the feature that distinguishes them • Success criteria: Correctly classifies both and names a distinguishing feature (not a surface trait). • Evidence: Exit slips sorted secure / partial / not-yet. • Feedback / adjustment: Re-teach with a two-column feature chart if under 70 percent distinguish correctly; Primer next lesson. Differentiation Representation: Provide the feature chart pre-filled with icons for lower-literacy readers. Action & expression: Let students classify by placing a token in a column or by writing. Engagement: Use systems students meet daily in the UAE (metro gate, weather app, voice assistant). People of Determination: Offer a two-choice token board and reduce the exit ticket to one system with support; allow verbal answers. EAL: Bilingual glossary; sentence frame 'This is a ___ system because the logic is ___'. Stretch / next tier: Ask students to find a system that is hard to classify and argue both sides using features.
